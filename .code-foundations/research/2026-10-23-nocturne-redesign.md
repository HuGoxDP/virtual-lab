модерацию и историю версий.

- **Статус:** draft
- **Ещё открыто:** ничего — бывшие открытые вопросы решены при планировании (раздел в конце).

## Дизайн-система (общее для обоих релизов)

- **Токены Nocturne** из `part01.style.txt` — источник истины для внешнего вида:
  `--color-bg #161826`, `--color-surface #232532`, `--color-text #e9e9ed`, `--color-accent #9184d9`,
  тональные ramps neutral/accent, отступы `--space-*` (шаг 2.8px), радиусы 4/8/14, тени-обводки.
- **Компонентные классы:** `.btn` (+ `primary`/`secondary`/`ghost`/`icon`/`block`), `.input`, `.field`,
  `.seg`, `.tag`, `.card-*`, `.table`, `.dialog`, `.hr` (линия с затуханием к краям — «подпись» Nocturne).
  Главная кнопка — **обводка акцентом, не заливка**.
- **Шрифт:** Inter 400/500, кириллица обязательна.
- **Иконки:** Phosphor (regular) вместо эмодзи.
- **Цвета статусов** (из прототипа): опубликовано `#8fdcb4`, на проверке `#e5c887`, черновик `#b2b6ca`,
  возвращено/ошибка `#f0b4b4`, успех `#7ed6a6`.
- **Анимации:** `vl-rise`, `vl-toast`, `vl-orbit`, `vl-twinkle`, `vl-slide-in` (определены в третьем
  `<style>` прототипа).
- **Адаптивность:** все экраны прототипа работают на узкой ширине. На мобильном у страницы сценария
  липкая нижняя кнопка «Запустити», у админки — бургер-меню.

**Ограничение:** шрифты и иконки отдаются с собственного origin, без CDN. Прототип грузит Phosphor с
unpkg, но `nginx/csp.conf` измерен и строг. Сторонний origin в нём — это решение по CSP, а не
побочный эффект вёрстки.

- Hero: тег кафедры, заголовок, подзаголовок, три счётчика. Значения «N сценаріїв у каталозі» и

- «Каталог сценаріїв» + сортировка-сегмент «Нові / За назвою». Фильтрация и пагинация уже серверные,
  поэтому сортировка тоже должна быть серверной.
- Чипсы категорий с иконкой и счётчиком; горизонтальный скролл на узком экране.
- Строка «Знайдено N сценаріїв».
- Карточка: превью 16:10 (картинка или градиент категории), бейдж «WebGL», размер архива, kicker
  категории + версия, название, краткое описание, автор, кнопка «Запустити». Клик по карточке ведёт на
  страницу сценария, «Запустити» — сразу в viewer.
- Пустое состояние «Нічого не знайдено» + «Скинути фільтри».
- Футер: о проекте, контакты, «Розробникам» → панель администрирования.
- Тосты: «Посилання скопійовано» и т.п.

### Страница сценария (`/scenario/:id`, новая; прототип «Сторінка сценарію», макет 2b)
Заменяет нынешнюю модалку деталей.
- Шапка: «← Каталог», хлебные крошки «/ Категорія / Назва», логотип.
- Баннер-превью с градиентом в фон, контент наезжает на баннер.
- Kicker категории, заголовок, строка мета (автор, дата обновления, версия), полное описание.
- «Що всередині» — 3 пункта: иконка + заголовок + подпись.
- «Суміжні сценарії» — 2 штуки: сначала из той же категории, потом из других.
- Липкая боковая панель: «Запустити симуляцію», «Відкриється у браузері…», таблица мета (версия,
  автор, размер архива, оновлено, ID), «Копіювати посилання», «Завантажити архів» (публичный
  `/scenarios/<sha256>.zip`).
- Блок «Вимоги» не нужен (макет 2b явно его убрал).

### Viewer (`/play/:id`, макеты 2c / 2d)
Функциональность viewer сохраняется полностью: отмена загрузки, перезапуск, полноэкранный режим,
проверка WebGL2, восстановление после потери контекста, `?diag=1`, `?stream=1`, обязательный
`dispose()`. Меняется вид и добавляются элементы HUD:
- **Загрузка:** кольцо прогресса с процентом, название сценария, «Завантаження архіву — X з Y МБ»,
  полоска, подпись этапа, «Скасувати».
- **Сцена запущена:** «← Вийти»; плашка по центру сверху «Назва | NN FPS»; справа пауза / сначала /
  весь экран; слева снизу подсказки управления (только на широком экране).
- **FPS — настоящий**, считается из `Time.unscaledDeltaTime`.
- **Пауза — `Time.timeScale = 0`**, клавиша Space. Снятие паузы восстанавливает значение, которое
  было до неё (сценарий мог выставить своё).
- Декоративные «орбиты» и звёзды прототипа — только заглушка вместо канваса, в продукт не идут.

### Данные, которых публичной части не хватает
Страница и карточки требуют того, чего сейчас нет в `scenarios` или в API каталога:
- «Що всередині» — список `{icon, title, subtitle}`; сейчас такого поля нет;
- размер архива и дата обновления: `archive_bytes` и `updated_at` есть в таблице, но отдаются только
  в `GET /api/admin/scenarios`. Публичный `/api/catalog` отдаёт лишь `uploadDate`
  (`backend/server.js:165`, `:241`);
- иконка и порядок категории (сейчас категория — пара колонок `category` / `category_label` в строке
  сценария, отдельной сущности нет);
- `image_url` есть, но пуст у всех строк (`PLAN.md` §2.4).

В релизе 1 эти поля заполняются вручную или скриптом. Формы для них появляются в релизе 2.

## Релиз 2 — админка

### Вход (прототип «Вхід», макет 2e)
- Две колонки: слева форма «Код доступу» (моноширинный, верхний регистр), справа иллюстрация с
  пояснением, как работает публикация.
- Ошибка неверного кода — в плашке под полем.
- Блок «Демонстраційні коди» — **только в прототипе**, в прод не идёт.
- Сессия: в макете — «Сесія діє 12 годин». Сейчас токен хранится в `sessionStorage` и живёт до
  закрытия вкладки.

### Роли и доступ
- **Автор:** видит только свои сценарии; создаёт, загружает архив, правит метаданные, подаёт на
  проверку. Опубликованный сценарий правит только через черновик.
- **Модератор:** видит всё; публикует, возвращает с комментарием, снимает с публикации, управляет
  категориями и кодами доступа.
- **Экран «Доступ»** (новый, в макетах его нет): список кодов (имя, роль, создан, последний вход),
  выдать, отозвать. Код показывается один раз, хранится хешем.
- Имя автора на карточке берётся из владельца кода.
- Коды — это publish keys, которые нужны редактору для Publish (`PLAN.md` §2.6). Требование: один и
  тот же авторский код работает и для входа в админку, и для публикации из WebEngineTSEditor.

### Статусы
`draft` (Чернетка) → `review` (На перевірці) → `published` (Опубліковано) или `rejected` (Повернуто,
с комментарием модератора). Снятие с публикации возвращает в `draft`. Статусы «Сховано» и «Тільки за
прямим посиланням» из 2f/2j **не делаем** (по прототипу). Каталог показывает только `published`.

### Экраны (по боковому меню прототипа)
- **Дашборд:** приветствие; счётчики «Опубліковано / На перевірці / Чернетки» (для автора — свои,
  для модератора — все); «Остання активність»; «Швидкі дії».
- **Сценарії** (прототип + таблица 2f): чипсы статусов со счётчиками, фильтр по категории, строка со
  статусом-пилюлей, «редагувати» / «переглянути». Массовые действия: опубликовать, снять, сменить
  категорию, удалить.
- **Редактирование** — вкладки:
  - *Метадані* (2g): название, ID, категория, версия, краткое описание со счётчиком (до 160),
    полное описание, **«Що всередині»** (редактор трёх пунктов), превью (загрузка, PNG/JPG 16:10,
    от 800 px), живое превью карточки «Як це побачить студент», чек-лист «Готовність до публікації».
  - *Файл* (2h): текущий архив, замена drag-and-drop с прогрессом, **история версий с откатом**,
    содержимое архива, предупреждение о большом архиве.
  - *Перевірка* (2i): статические проверки сервера (структура и манифест, entry, ресурсы внутри
    архива, несжатые текстуры, размер) + «Тестовий запуск» в браузере модератора с метриками (время
    до первого кадра, средний FPS, память GPU, ошибки в консоли), результаты сохраняются к версии.
    Журнал проверки.
  - *Публікація* (2j + прототип): текущий статус; у автора — «Подати на перевірку»; у модератора —
    комментарий, «Опублікувати», «Повернути на доопрацювання»; «Зняти з публікації»; «Відкрити в
    каталозі»; **история решений** (кто, что, когда, комментарий).
- **Черга модерації** (прототип + 2k): карточки поданных сценариев с итогом автопроверки и
  предупреждениями, «Опублікувати / Розглянути / Повернути»; пустое состояние. Таблица «Нещодавні
  рішення» — из 2k.
- **Завантаження** (прототип + 2l): шаги Файл → Метадані → Перевірка → Публікація; drop-зона; поля,
  прочитанные из манифеста; сохранение черновиком; «Надіслати на модерацію».
- **Напрями / Категорії** (2m): название, slug, иконка, число сценариев, видимость в каталоге,
  порядок (определяет порядок чипсов). Категорию со сценариями удалить нельзя — её можно скрыть.
- **Мобильная версия:** узкая шапка с бургером, выезжающее меню (есть в прототипе).

## Ограничения (из `CLAUDE.md` репозитория)

- Angular 21, standalone, `OnPush`, **zoneless**: состояние UI — сигналы.
- Фильтрация, поиск, пагинация и сортировка каталога — на сервере.
- Движок импортируется только из `"WebEngineTS"`; новые возможности движка — через
  `ENGINE-GAPS.md` и релиз WebEngineTS, не обходом в платформе.
- Строки интерфейса — украинские, код и комментарии — английские.
- Схема меняется только миграциями в `backend/migrations/`.
- CSP (`nginx/csp.conf`) измерен по директивам; шрифты, иконки и загрузки превью должны в него
  укладываться.
- Каталожная модель платформы (`scenario.model.ts`) отделена от `IScenarioManifest` движка — новые
  поля относятся к платформе.
- Тесты: 60 frontend + 232 backend + 35 Playwright. E2E опираются на текущую разметку каталога,
  модалки и админки, поэтому редизайн их сломает и обновляется вместе с ними.

## Риски

- **Релиз 2 — крупная бэкенд-работа**, а не вёрстка: роли, статусы, версии, журнал и категории
  меняют схему и почти все admin-эндпоинты. Он же разблокирует Publish в редакторе, так что его форма
  ограничена дизайном publish keys (`WebEngineTSEditor/docs/unity-editor-plan.md` §7).
- **Пауза через `Time.timeScale`** конфликтует со сценарием, который сам управляет временем.
- **Метрики тестового запуска** зависят от железа модератора; сравнимы только с пометкой устройства и
  сборки движка (`BuildInfo.builtAt`).
- **История версий и GC:** сборщик архивов (`/api/admin/storage/gc`) удаляет объекты, на которые не
  ссылается ни одна строка. Старые версии должны считаться ссылками, иначе откат укажет на удалённый
  файл.
- **Безопасность:** авторский код в чужих руках позволяет загружать произвольный JS, который
  выполняется на origin платформы. `PLAN.md` §2.9 требует изоляции сценариев **до** появления
  publish keys.

## Решения по бывшим открытым вопросам (2026-10-23, при планировании)

1. **Изоляция сценариев (§2.9) — фаза релиза 2.** Viewer и тестовый запуск исполняют сценарий в
   iframe на отдельном origin. Авторские коды включаются только после неё: иначе архив автора,
   запущенный в браузере модератора, читает его код из `sessionStorage`.
2. **Существующие строки — без владельца.** `is_published = true` → `published`, `false` → `draft`.
   Ими управляют модераторы. `author` остаётся отображаемым именем (по умолчанию — имя владельца
   кода), модератор может его править.
3. **Версии хранятся все**, удаление — вручную модератором. Каждая версия — ссылка для GC.
4. **«Що всередині» — 0–6 пунктов.** Иконка выбирается из фиксированного набора ~40 иконок Phosphor
   (сетка-пикер); тот же набор — для категорий. Самостоятельно хостятся только эти иконки, а не весь
   шрифт (5,5 МБ CSS).
5. **Сессия — как сейчас:** код в `Authorization: Bearer`, в браузере — `sessionStorage` до закрытия
   вкладки. Тот же код работает для Publish из редактора. Надпись «Сесія діє 12 годин» не переносим.
6. **Тексты и логотип — из прототипа**, собраны в один конфиг сайта. Кафедра — полное название из
   футера («…програмної інженерії та економічної кібернетики»). Владелец сверяет их перед деплоем.
7. **Лимит архива — 200 МБ** (`MAX_ARCHIVE_BYTES` по умолчанию). Интерфейс берёт цифру из API, а не
   хардкодит. Сейчас: бэкенд — 2 ГБ (`backend/server.js:97`), nginx — `client_max_body_size 512m`.
8. **Данные релиза 1:** пустые блоки скрываются. Иконки шести существующих категорий засеваются
   миграцией. В текущую `/admin` добавляется только поле «Що всередині».

Открытых вопросов нет.

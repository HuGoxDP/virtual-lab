# Ручна перевірка у браузері

Тут **тільки те, що автотести перевірити не можуть**: рендеринг WebGL, втрата
графічного контексту, повний екран, пастка фокуса, `sendBeacon` при закритті
вкладки. Решта (198 тестів) виконується командою `npm test` і не потребує вашої
участі.

**Перед початком:**

```bash
docker compose up -d
```

Токен для адмінки візьміть з `.env`:

```bash
grep ADMIN_TOKEN .env
```

Позначайте пройдене прямо в цьому файлі.

> **Про id зі зведеної бази.** У вашій поточній базі два сценарії мають id з
> пробілом (`Benchscene2 complexmodel`) — `db/init.sql` виконується лише на
> порожньому томі, тож виправлені слаги застосуються тільки після
> `docker compose down -v`. Посилання нижче враховують це.

## 1. Каталог — <http://localhost:8044/catalog>

- [ ] Сторінка відкривається, картки сценаріїв видно, зображення завантажуються.
- [ ] Клік по чипсу **Test** лишає тільки тестові сценарії; **Всі сценарії** повертає всі.
- [ ] Ввід у пошук фільтрує список; запит іде **один раз** після паузи, а не на кожну літеру
      (DevTools → Network, фільтр `catalog`).
- [ ] Перемикач ☀️/🌙 змінює тему, і вона **лишається** після F5.

### 1.1 Клавіатура (важливо — це те, чого автотести не бачать)

- [ ] Tab доводить фокус до картки сценарію, навколо неї видно рамку.
- [ ] Enter на картці відкриває вікно; Space теж.
- [ ] У відкритому вікні Tab **не виходить** за його межі — циклиться всередині.
- [ ] Shift+Tab з першого елемента переводить на останній, а не за вікно.
- [ ] Esc закриває вікно.
- [ ] Після закриття фокус повертається **на ту саму картку**, з якої відкривали.

## 2. Перегляд сценарію — <http://localhost:8044/play/solar-system>

- [ ] Кільце прогресу **плавно рухається від 0 до 100%**, а не стоїть на нулі.
      *Це був реальний баг: під зоні-less режимом колбеки прогресу не викликали
      перемальовку. Якщо кільце знову застигло на 0% — регресія.*
- [ ] Під кільцем видно «Завантаження: N MB», число зростає.
- [ ] Після завантаження сцена рендериться, камера обертається мишею.
- [ ] Заголовок сценарію з'являється зверху.

Перевірте прямий перехід (не з каталогу):

- [ ] F5 на цій сторінці → сцена вантажиться заново **і заголовок не порожній**.

### 2.1 Кнопки керування (правий верхній кут)

- [ ] **⟳** перезапускає сцену. У Network **нового завантаження архіву немає** —
      використовується буфер із пам'яті.
- [ ] **📊** вмикає накладку діагностики рушія (FPS, пам'ять); повторний клік вимикає.
- [ ] **🗖** розгортає на весь екран; Esc або 🗗 повертає.

### 2.2 Втрата графічного контексту

У консолі DevTools на сторінці сценарію:

```js
document.querySelector('canvas').getContext('webgl2')
  .getExtension('WEBGL_lose_context').loseContext();
```

- [ ] З'являється екран «Графічний контекст втрачено» з кнопкою «Перезавантажити».
- [ ] Кнопка справді перезавантажує і сцена стартує знову.
      *Без цього втрачений контекст просто мовчки заморожував картинку.*

### 2.3 Скасування завантаження

- [ ] Відкрийте <http://localhost:8044/play/Benchscene2%20complexmodel> (28 МБ) і **під час**
      завантаження натисніть «← Каталог». У Network запит має стати `(canceled)`,
      а не догойдатися до кінця.

### 2.4 Помилкові стани

- [ ] <http://localhost:8044/play/no-such-scenario> → «Сценарій не знайдено».
- [ ] Якщо є браузер без WebGL 2 (або вимкніть апаратне прискорення) → повідомлення
      про вимоги до браузера, а не «сирий» текст помилки.

## 3. Адмінка — <http://localhost:8044/admin>

- [ ] Без токена видно форму входу.
- [ ] Невірний токен → «Невірний токен», форма лишається.
- [ ] Правильний токен → таблиця сценаріїв.
- [ ] У таблиці видно **приховані** сценарії (яких немає в каталозі).
- [ ] Стовпець «Архів» показує короткий хеш і розмір; «Маніфест» — id з `manifest.json`.
      *Він навмисно **не збігається** з id каталогу — це не помилка.*

### 3.1 Повний цикл публікації

- [ ] **+ Новий сценарій** → id `probe-manual`, назва, категорія `test`, підпис `Test` → Зберегти.
- [ ] Рядок з'явився. Натисніть **Архів…** і виберіть будь-який ZIP сценарію
      (можна завантажити готовий: <http://localhost:8044/scenarios/8a569777f0d80aae23748e3e29344bc83cafebe454d933e36c9a6c7c76c41ed3.zip>).
- [ ] Видно **смужку прогресу** завантаження, потім повідомлення з sha256 і розміром.
- [ ] Завантажте той самий файл ще раз → у повідомленні є «дедуплікація».
- [ ] Спробуйте завантажити будь-який **не-ZIP** файл → «Файл не є ZIP-архівом», нічого не зламалось.
- [ ] Натисніть стан → «Опубліковано». Сценарій з'явився в <http://localhost:8044/catalog>.
- [ ] **Видалити** → питає підтвердження; після «Скасувати» нічого не сталося; після «ОК» рядок зник.

### 3.2 Токен

- [ ] DevTools → Application → Session Storage: є `adminToken`.
- [ ] Local Storage: `adminToken` там **немає**.
- [ ] Закрийте вкладку, відкрийте `/admin` знову → знову форма входу.

## 4. Телеметрія

- [ ] Відкрийте будь-який сценарій, дочекайтесь запуску, поверніться до каталогу.
- [ ] Перевірте, що сесія записалась і закрилась:

```bash
curl -s -H "Authorization: Bearer $(grep '^ADMIN_TOKEN=' .env | cut -d= -f2)" \
  http://localhost:8044/api/telemetry/summary
```

- [ ] `launches` зросло, `medianDurationMs` більше нуля.
- [ ] Тепер відкрийте сценарій і **закрийте вкладку** (не переходьте назад).
      Повторіть запит вище — `completed` теж має зрости.
      *Це перевіряє `sendBeacon`: звичайний `fetch` під час закриття вкладки браузер скасовує.*

## Що робити, якщо щось не так

Позначте пункт як провалений і напишіть, що саме побачили. Автотести
(`backend: npm test`, `frontend: npx ng test --no-watch`) покривають логіку —
якщо вони зелені, а пункт тут червоний, проблема саме в браузерному шарі, і це
корисна знахідка.
